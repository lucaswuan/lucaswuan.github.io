01 / CONTEXT

Overview

I’m an RTL design member of UWASIC, the University of Waterloo’s chip design team, which is building a ray-tracing ASIC. I wrote the chip’s functional-unit control module in SystemVerilog. It sits between the micro-op channel and the three arithmetic units: the ALU, the multiplier, and the CORDIC unit.

For each micro-op, the module decides which unit should run it, collects its operands, hands the work over when that unit is ready, and writes the result back to the register file when the unit finishes. Before this, I completed UWASIC’s digital-design onboarding project, an SPI-controlled PWM peripheral.

02 / CONTRIBUTION

The work

Decoding 11 micro-ops

Each micro-op is decoded into a target unit and, for units that run more than one operation, a 3-bit opcode for that unit.

  • ALU: add, subtract, equal, not equal, less than, and greater than or equal.
  • Multiplier: multiply.
  • CORDIC: divide, square root, cosine, and magnitude.

Operands

Operands normally come from the register file’s two read ports, addressed by the micro-op’s two source registers. Scalar macro-ops carry their operands on the micro-op channel instead, so a direct flag switches a mux between the register file and the channel. The operands, opcode, and format field go to all three units, but only the selected unit sees a valid request.

Valid/ready handshakes

Each unit connects through the same SystemVerilog interface, with a valid/ready handshake on the request side and a done signal on the response side. The module passes the selected unit’s ready signal back up the micro-op channel, so a micro-op is accepted only in a cycle where it is valid and that unit is ready. In that cycle, the module also records the micro-op’s destination register for that unit, so the result is written to the right place when it arrives.

Writing results back

When a unit finishes, the module writes its result to the destination register it recorded and signals on the micro-op channel that the operation is done. The register file has one write port, so writeback uses a fixed priority: the ALU first, then the multiplier, then the CORDIC unit.

03 / REFLECTION

Outcome

The functional-unit control module is written, connecting the micro-op channel to all three arithmetic units. I’m now supporting the verification team as the module is tested and integrated into the chip’s RTL-to-GDS flow.
