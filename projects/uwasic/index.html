01 / CONTEXT

Overview

I’m an RTL design member of UWASIC, the University of Waterloo’s chip design team. My current work is functional-unit RTL for a ray-tracing ASIC, collaborating with the verification team toward passing functional tests and a lint-clean RTL-to-GDS flow.

Before that work, I completed a digital-design onboarding project: a Verilog SPI Mode 0 peripheral with register-controlled outputs and PWM. That project connected RTL implementation, automated verification, and physical-layout generation.

02 / CONTRIBUTION

The work

The peripheral

The onboarding peripheral has five registers and sixteen outputs. I implemented SPI Mode 0 communication and two-stage clock-domain crossing to move signals between clock domains.

  • Verilog RTL for the SPI peripheral and output controls.
  • Register interface for configuring peripheral behavior.
  • Two-stage CDC for signals crossing clock domains.

Verification & tooling

I wrote Python/cocotb tests for 3 kHz PWM, checking 0%, 50%, and 100% duty cycles as well as output-enable behavior. I configured Tiny Tapeout and GitHub Actions to run simulation tests and generate GDS layout files.

Current work

I’m now applying that foundation to functional-unit RTL for UWASIC’s ray-tracing ASIC. This is ongoing team work; the completed peripheral and its verification flow are the onboarding portion of the project.

03 / REFLECTION

Outcome

Completed the SPI/PWM onboarding project with automated simulation tests and GDS generation. The next stage is continuing functional-unit design and verification with the UWASIC team.
